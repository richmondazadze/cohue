## Defects / requests for lead
1. **Replay contract blocks the historical snapshot**: `apiContracts.replay.input` is `{ atSequence: SequenceSchema }` (number, not `z.coerce`), but GET input arrives as a query string, so every `/api/missions/:id/replay?atSequence=N` returns 422 "Request does not match the contract". The UI shows this honestly and keeps the event list; fix needs `z.coerce.number()` in the contract (lead-owned) — no frontend change required afterwards.
2. Creator has no read path for an invitation's `localized` items (getInvitation is INVITATION-only), so translation approval works only after the creator opens the invitation link in their own browser. A creator-scoped list (e.g. on proposal invitations or snapshot) would let the theater approve directly.
3. Synthesis needs `canonicalTextHash`, which only `localized` items carry; with no translation (same language or no Gemini) there is no Listen for the original text. Exposing the canonical text hash on the invitation would fix this.
4. Showcase and live use different scopes but this device's stored participant id is unscoped; /me in showcase will show the "no longer has access" state. Acceptable for now; a session-reported participant id (earlier question 1) would remove it.
