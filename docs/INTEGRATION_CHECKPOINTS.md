## Ownership and shared-file protocol

Frontend owns app page/layout/UI files, components/features/client/public, tests/frontend and tests/e2e/frontend; backend owns server, app/api route.ts, drizzle and drizzle.config.ts, scripts/worker, tests/backend and tests/e2e/backend. Lead owns schemas/fixtures/root configuration/CI/tests/contracts/tests/e2e/integration and cross-team specs. Both may append their own docs/status/<role> report. Frontend does not create backend handlers; backend does not change CSS/components. Only lead changes shared contracts/root packages/config; request deltas with reason, exact proposed schema and compatibility impact via user relay. Design source files are frozen, production visual implementation remains frontend-owned.

Handoffs are a deliberate serialized exception to exclusive ownership: first write your own milestone note, then `npm run handoff:append -- docs/status/frontend/I1.md` (or backend equivalent). Script takes exclusive `.handoff-update.lock`, checks current handoffs match, re-reads latest and writes both identically. If another writer holds the lock, continue owned work and retry later; do not delete another writer’s lock. If handoffs mismatch/crash left a lock, stop and ask lead to reconcile, do not blindly copy stale content. Append exact results, commit baseline, migrations/provider/deployment status and immediate next step, no secrets. `npm run check:foundation` must pass before commit. Stage/commit both handoffs with only your owned paths, never `git add .` in parallel. No simultaneous manual editing of handoffs; lead uses same serialization at integration milestones. Current summary is timestamped at foundation; later appended milestones supersede per-module status.

Working slices integrate continuously in the same app and current contracts. Lead reviews each checkpoint and reruns combined checks after user-relayed specialist reports; no assumption of messaging or end-of-project merge. If an API changes, producer, consumer, fixture, tests and manifest update in one coordinated lead-reviewed revision. Do not let a consumer silently invent an adapter contract.

## Common verification

Before each checkpoint: `npm run check` (frozen source hashes, synchronized handoffs, exact dependency pins, lint, typecheck, Vitest, production build), `npm audit --audit-level=high`, and `npm run test:e2e` on built app. Add meaningful backend actual-DB tests, frontend reducers/browser and lead integrated browser flows as they exist; no skipped/mocked tests count as deployed proof. CI YAML exists but no remote/hosted run is implied. Enforce Node24 in CI/deploy, npm lockfile, reviewed dependency overrides. Preserve exact command results and conditions in status notes. Existing foundation smoke is one plain page only, not product E2E coverage.

## Lead integration harness

`tests/e2e/integration/support/contract-client.ts` prepares every request from `apiContracts` (path params, input, Idempotency-Key) and rejects any response that is not the documented success body or an ApiError with its mapped HTTP status. `device.ts` gives each simulated phone its own cookie jar. `i2-join-create-match.spec.ts` and `i3-consent-repair-activate.spec.ts` drive the real API: join, create, start, proposal, exact replay and changed-payload conflict, creator-only theater, exhausted no-solution, then select, share link, non-consuming preview, second-device redemption, accept, decline, genuine repair, reconsent on changed group terms, activation replay, room and task version conflict.

The specs need a running backend on an isolated, disposable database, because they create LIVE participants labelled `[integration <run>]` and fail rather than respond for foreign participants. Run `npm run build && npm run test:e2e` with the server environment set, or point `COHUE_INTEGRATION_BASE_URL` at a staging deployment. Missing API routes produce a skip with the reason, never a pass; set `COHUE_REQUIRE_INTEGRATION=1` at I2 and later so a missing backend fails the run. `COHUE_INTEGRATION_TIMEOUT_MS` (default 90000) bounds waits for committed state. A local pass is not D7 evidence.
